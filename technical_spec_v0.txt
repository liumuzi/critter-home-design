Critters Prototype 技术说明文档（完整版）
文档信息
阅读说明：本文中「游戏内 AI」指运行时对玩家可见的 LLM 对话生成；「研发流程 AI」指制作阶段使用的辅助编程与生成式美术/动画工具，二者层次不同，文中分章叙述，避免混淆。
一、项目概述
Critters Prototype 是一款基于 Web 的虚拟小动物互动原型。玩家在场景中与 NPC 互动（如靠近、赠礼、抚摸、家具的摆放与收回等），小动物通过自然语言表达主观感受；其台词与信任度、需求水平、短期与长期记忆、世界事件时间线相结合，形成连续、可个性化的情感反馈体验。
技术栈：React 19、TypeScript、Vite 7；本地 Node HTTP 服务提供 LLM 与语音相关代理；Nginx 用于生产环境反代；测试使用 Vitest。
与 README 的关系：若根目录 README.md 仍写有「LLM 占位回复」等旧描述，以本文及 `src/services/dialogueService.ts` 实际实现为准。
二、系统总体架构
2.1 逻辑分层
1. 规则与模拟层负责需求衰减、动机与行为、信任数值变化、WorldEvent / ShortTermEvent 的维护、活动状态等。该层不依赖 LLM 即可完成核心闭环；LLM 离线时游戏仍可运行。
2. 叙事与表达层（游戏内 LLM）在特定 DialogueTrigger 下，根据 gameState 快照拼装上下文，调用兼容 OpenAI Chat Completions 的接口，生成独白式中文台词；可选进行二次 LLM 调用做与事实一致性的轻量判别；失败时使用本地预设文案兜底。
3. 表现层全屏对话（DialogueOverlay）与非阻塞气泡（speechBubbleService），含加载态、过期时间与请求去重/冷却。
2.2 核心文件索引
历史代码位于 src/_old/，不作为当前 MVP 主线在本文展开，除非单独说明为演进对比。
三、游戏状态与 LLM 上下文（智能 NPC 的数据基础）
LLM 的输入不是长段自由聊天历史，而是结构化游戏状态，主要包括：
角色档案 `CritterProfile`：名称、物种、性格文本、偏好列表等。  
即时状态：NeedLevels 与 CritterActivity，在 Prompt 中经 needsDescription、activityLabels 转为自然语言。  
长期记忆 `LongTermMemory`：信任度 0–100、对玩家的印象 playerProfile、significantEvents、cognitions 等。  
短期经历：ShortTermEvent[] 经 buildSummary 压缩为「你经历过的事」摘要。  
世界事件：WorldEvent[] 经 buildEventTimeline 按「玩家 / 该小动物 / 其他」分类并截取最近若干条，形成「最近这个世界里发生的事」。
上述设计支撑竞赛维度中的智能 NPC（情境响应）与玩家体验个性化（同一触发下，因性格、信任、记忆不同而台词不同）。
四、游戏内 LLM：模型、接口与部署
4.1 模型与 API
使用 OpenAI Chat Completions 兼容协议（POST，解析 choices[0].message.content）。  
默认模型名：deepseek-chat；上游 URL 与模型名均可通过环境变量覆盖。
4.2 前端运行时配置（dialogueService.ts）
若配置 VITE_MODEL_API_KEY：可向 VITE_MODEL_API_URL 直连（缺省为 DeepSeek 官方地址），请求头携带 Authorization: Bearer …。  
若无前端 Key：请求同源路径 `/api/chat/completions`，避免将密钥打入前端构建产物。
4.3 服务端代理与安全（server/apiServer.ts + nginx.conf）
Node 在 127.0.0.1:3001 提供 POST /chat/completions：解析客户端 JSON 后强制覆盖body.model 为环境变量 MODEL_MODEL，使用 MODEL_API_KEY 转发至 MODEL_API_URL，并将上游状态码与 body 返回客户端。Nginx 将 /api/chat/completions 反代至该端口并设置较长读超时，以适应 LLM 延迟。
语音相关：同服务在凭证齐全时可提供 /ali-speech-config（阿里云语音 Token 等），与对话 LLM 为独立能力链。
4.4 主请求与校验参数（以代码为准）
若仓库内其他文档（如 docs/LLM_PROMPTS.md）中的 token 或超时与上表不一致，以 `constants.ts` 与 `dialogueService.ts` 为准。
五、提示工程（Prompt Engineering）
5.1 消息结构
每次主对话为两条消息：
1. System（`buildSystemPrompt`）注入角色设定、当前活动与需求自然语言描述、信任阶段与对玩家印象、世界事件时间线、记忆摘要（经历、认知总结、印象深刻的事），并规定语气、长度、禁止 JSON/旁白/空泛提问等。
2. User（`buildUserPrompt`）绑定当前 `DialogueTrigger` 的场景说明，例如：主动靠近玩家、收到礼物、被抚摸、与偏好相关的家具被摆放或收走等，使生成内容锚定具体游戏事件。
5.2 触发类型与竞赛表述对应
DialogueTrigger 与场景描述、Fallback 文案一一对应，保证 NPC 反应与玩家操作类型一致，属于事件驱动的程序化叙事生成（当前实现形态为台词生成，而非关卡几何或任务图的自动生成）。
六、生成管线、一致性校验与降级（核心算法叙述）
6.1 主生成
callLLM 使用 fetch 与 AbortController 实现超时中止；失败返回 null。
6.2 一致性校验（Guardrail）
validateDialogueLine 将「触发场景 + 事件时间线 + 待检验台词」拼为判别用提示，要求模型仅输出「通过」或「不通过」；若返回文本包含「不通过」则判为未通过。若校验请求失败（null），实现上默认视为通过，避免长时间无反馈。
6.3 重试与兜底
generateDialogueLine 最多两轮：首轮生成后校验；不通过则第二轮重新生成且跳过校验直接采用；仍无有效文本则调用 `generateFallback`，从该触发类型下多条预设中文模板中随机返回。
可概括为：生成 → 判别 → 有限重试 → 模板兜底，在表现力、事实约束与可用性之间折中。
七、游戏内具体集成（玩家可感知实现）
`DialogueOverlay`：对话激活且无文本时，从 gameState.getSnapshot() 读取该小动物档案、长期记忆、需求、短期事件、世界事件与活动，调用 generateDialogueLine，展示加载态与最终文本。  
`speechBubbleService`：异步请求同一生成函数；用 pendingRequests 防并发；对 arrived_at_player 等使用 `CRITTER_DIALOGUE_COOLDOWN_MS`（180 s） 等常量限频；气泡带 `SPEECH_BUBBLE_DURATION_MS`（10 s） 过期；失败仅告警不阻塞主循环。
设计原则（与仓库内设计文档一致）：行为选择、即时情绪、信任演化等由规则系统负责；LLM 仅增加叙事层，即使 LLM 不可用，仍可通过 Fallback 维持表达层不断裂。
八、设计理念与相关研究
以下不声称本项目复现了某篇论文的完整训练或模型架构，仅说明问题域与工程手段上的呼应，便于评审理解深度：
角色一致性（Persona）通过 System Prompt 显式注入性格、喜好、信任阶段与长期记忆，使输出与「人设 + 关系阶段」对齐；与强调人设对齐的 LLM 角色扮演研究在目标上一致，本项目以提示工程 + 游戏状态机实现，无额外模型微调。
主观表达与客观事实的分离主生成侧重第一人称独白；validateDialogueLine 以独立短提示侧重「是否与已记录事件矛盾」，在工程形态上类似「生成与一致性检查分层」，但本项目为两次 API 调用的轻量方案，非论文中的数据合成、对比学习或强化学习训练管线。
引用外部论文时，建议明确写法：「在提示与管线层面与××方向的研究目标形成呼应，而非采用其训练方法。」
九、研发流程中的 AI 使用
本章性质：描述作品制作与工程实现过程中对 AI 工具的使用，与第三至七章的运行时游戏内 LLM 为不同层次。
9.1 AI 辅助编程
团队在开发 Critters Prototype 过程中使用 AI 辅助编程（如基于大模型的代码补全、对话式重构与文档化建议等），用于加速接口梳理、样板代码与多方案比较。合入仓库前均经人工审查与测试；运行时架构、密钥经服务端代理、状态一致性等仍以人工决策为准。该实践体现软件工程维度对 AI 的综合运用，可与「智能 NPC」叙述并列，展示团队对 AI 工具链的掌握。
9.2 美术与过场动画（AIGC）
作品的美术过场动画采用 AI 生成式图像/视频（AIGC） 作为创作流程的一部分（具体工具与素材比例以参赛附件为准），经团队筛选、剪辑、调色、合成与时间轴编排后集成到成品中，用于在有限人力下完成氛围与情绪传达，并与程序侧节奏（如对话 overlay、气泡时机）对齐。
9.3 动画的 AI 辅助
部分角色或界面动画在制作中使用了 AI 辅助（如动作参考、关键帧建议或动效参数探索等，按团队实际做法在定稿时可改为更精确一句）。最终曲线、时长及与游戏逻辑的绑定由人工在工具或代码中定稿。
9.4 合规建议
在作品说明或 README 中建议简要披露「开发阶段使用 AI 辅助编程及 AIGC 美术/动画」，并对照赛规核对对 AI 素材比例、署名与原创性的要求。

十三、结语
Critters Prototype 在产品层将大语言模型深度用于 NPC 事件驱动台词生成：结构化状态注入、双阶段生成与一致性校验、服务端密钥代理与多级降级及冷却策略，在无需微调的前提下实现可演示、可解释的智能对话。在制作层，团队综合运用 AI 辅助编程 与 AIGC 美术及过场、部分动画辅助，缩短迭代周期并丰富视听表现。两类 AI 应用相互独立又共同体现本项目对人工智能技术的全链路运用，可作为比赛技术说明的完整叙述基础。
