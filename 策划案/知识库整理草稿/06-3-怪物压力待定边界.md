# 怪物压力待定边界

## 当前结论

怪物系统准备重新设计，目前没有最终定稿。旧《怪物设计文档 V0.1》内容过重，且会议记录中已有“当前怪物系统过于复杂、与无战斗玩法不符、会拖慢节奏”的反馈。因此本轮不再把旧怪物 A/B/C、完整警觉状态机、报警怪等写入当前执行方案。

## 仍可保留的设计边界

- 野外需要压力，但压力应服务于撤离决策，不服务于战斗。
- 玩家不能打怪，所以危险必须可读、可控、可归因。
- 惩罚不能过重，安全背包、掉落追回、光源撤离提示都是容错手段。
- “近距惊险但没被抓到”的反馈值得保留。
- 怪物重做后应和光源、声音、负重至少一个系统产生关系。

## 不应当前落地的旧内容

| 旧内容 | 处理 |
|-|-|
| 怪物A/B/C具体形象与数值 | 暂停 |
| 完整警觉值公式 | 暂停 |
| 巡逻/警觉/追击/搜索/返回完整状态机 | 暂停 |
| 报警怪向周围怪物广播玩家位置 | 暂停 |
| 复杂听力/视野组合配置 | 暂停 |

## V1可以先做的压力接口

| 接口 | 说明 |
|-|-|
| danger_trigger_area | 关卡中可配置危险区域 |
| near_miss_feedback | 近距擦身反馈，不一定造成失败 |
| light_exposure_factor | 光源暴露风险，先保留参数 |
| sound_exposure_factor | 声音暴露风险，先保留参数 |
| weight_exposure_factor | 负重增加风险，先保留参数 |

这些接口可以先供野外关卡和光源系统预留，不要求立刻实现复杂怪物AI。

## 后续重设计需要回答

- 怪物是否仍然需要“视野锥”？
- 怪物是巡逻实体、区域危险，还是事件触发？
- 玩家失败条件是被抓、被赶回、丢失背包，还是强制撤离？
- 光、声音、负重分别如何影响危险？
- 怪物密度如何避免音效和视觉压力过载？
